# 랭킹 릴스 만드는 법 (계정 myeotwi.ya · 몇위야)

하루 5편을 올린다(Gyan 결정 2026-10-31). 예약 작업 **하나**가 매일 09:17 KST 에 새 세션을 열어 5편을 차례로 만들고, 각 편을 게시 시각(11:00 · 14:00 · 17:00 · 20:00 · 22:00 KST)으로 대기열에 넣은 뒤, 마지막에 `시각별 게시 실행`(.github/workflows/slots.yml)을 한 번 실행한다. 이 워크플로우가 시각마다 게시 워크플로우를 실행해 그 시각이 된 편이 올라간다. 사람에게 묻지 않는다(묻지 말고 가장 그럴듯한 쪽으로 정하고, 정한 것을 결과 보고에 적는다).

근거: 조사 결과(INSTA `주제/랭킹/조사_랭킹계정_20261030.md`) — 순위 이미지 1장을 8초 릴스로 올린 계정(tap.pick, 팔로워 1,955명)이 10만~400만 조회.

## 1. 소재 고르기
근거: 조사 결과(INSTA `주제/랭킹/조사_hot_click_20261030.md`) — 클릭이 많이 나오는 랭킹 계정(hot___click)은 "나는 / 내 것은 몇 위?" 를 바로 묻게 하는 주제를 쓴다. 한국은 또래와 비교하는 관심이 커서 나이대별 통계, "상위 1% · 10% · 50% 안에 드는 기준" 이 잘 읽힌다(Gyan 2026-10-30).

1. 이 폴더 `사용소재.md` 를 먼저 읽는다. 표의 `피함 끝` 날짜가 지나지 않은 소재(같은 분야 · 같은 달 자료)는 고르지 않는다. 오늘 이미 올린 편(같은 날짜 줄)과 **유형이 겹치지 않게** 고른다(하루 5편이 5가지 유형이면 가장 좋다).
2. 유형(이 가운데서 고른다)
   | 유형 | 보는 사람이 묻는 말 | 예 | 이미지 모양 |
   |---|---|---|---|
   | A 상위 N% 위치 | "나는 상위 몇 %?" | 연봉 · 순자산 · 예적금 · 소득 상위 1/10/50% 기준값(가능하면 나이대별) | 구간표(`layout: tier`) |
   | B 또래 비교 | "내 또래보다 나은가?" | 나이대별 평균 자산 · 저축액 · 혼인율 · 결혼 나이 · 키 · 몸무게 · 수면 시간 · 건강검진 수치 | 순위 목록 + 값 칸, 또는 구간표 |
   | C 자기 대입 | "우리 동네 / 내 직업 / 내 학교는 몇 위?" | 시군구 · 직업 연봉 · 대학 · 성씨 · 혈액형 · MBTI 비율 | 순위 목록(값 칸 있으면 씀) |
   | D 아는 이름 × 몰랐던 숫자 | "그게 그렇게 높아?" | 연예인 · 운동선수 공식 기록(연봉 · 음반 판매 · 시청률), 기업 평균 연봉 | 순위 목록 + 값 칸 |
   | E 돈 변천 | "옛날엔 얼마였어?" | 짜장면 · 최저임금 · 아파트값 · 등록금의 연도별 값 | 순위 목록 + 값 칸 |
   | F 사건 · 안전 | "우리 동네는 안전한가?" | 지역별 교통사고 · 화재 · 범죄 발생 건수(공식 통계) | 순위 목록 + 값 칸 |
   | G 브랜드평판 | "내 최애 브랜드는 몇 위?" | 한국기업평판연구소 월간 브랜드평판(치킨 · 라면 · 커피 · 아파트 …) | 순위 목록(1위 가림) |
   - G(브랜드평판)는 하루 5편 가운데 **최대 2편**만 쓴다
3. 후보 3개를 서로 다른 유형에서 찾고, 아래 점검에 "예" 가 가장 많은 것을 고른다(같으면 A · B 를 먼저)
   - 첫 줄만 보고 "나는 / 내 것은 몇 위(몇 %)?" 를 떠올리는가
   - 1위나 기준값이 뻔하지 않은가(맞혀 보고 싶은가)
   - 숫자가 놀라운가(예상보다 높거나 낮은가)
4. 조건(모두 맞아야 함)
   - 순위 · 값을 **공개 자료 원문 또는 기사로 확인**할 수 있다. 자료에 없는 순위 · 구간값을 지어내거나 계산 · 추정해 채우지 않는다(평균을 상위 50% 로 바꿔 쓰지 않는다 — 평균과 중위값은 다르다)
   - 공식 통계를 먼저 쓴다: KOSIS 국가통계포털, 통계청 가계금융복지조사 · 혼인이혼통계 · 사회조사, 국세청 국세통계(소득 백분위), 국민건강보험 건강검진통계, 부동산원, 경찰청 · 소방청 통계. 그다음 조사기관 보고서(오픈서베이 등) · 앱 순위(와이즈앱) · 언론 기사
   - 발표 시점과 조사 기간을 이미지 `source` 와 캡션에 쓴다. 해마다 나오는 통계는 가장 최근 판을 쓴다(브랜드평판은 30일 이내)
   - 사람 실명은 **공인의 공개된 공식 기록**(연봉 · 기록 · 판매량 등)만 쓴다. 사생활 · 외모 평가 · 이혼 · 질병 · 범죄 피해 · 미성년자는 쓰지 않는다. 사람 사진은 쓰지 않는다
5. 가능하면 출처를 2곳에서 대조한다. 1곳뿐이면 결과 보고에 "1곳 확인" 이라고 적는다

## 2. 자료 JSON (render.py 에 넣는 값)
```json
{
 "slug": "20261031_치킨브랜드평판",
 "badge": "2026년 10월 브랜드평판",
 "title": "치킨 브랜드 순위",
 "stat": "28개 브랜드 · 빅데이터 1,128만 개 분석",
 "hint": "BBQ · 교촌치킨을 제치고\n1위에 오른 브랜드는?",
 "items": ["1위 이름", "2위", "…", "10~15위"],
 "source": "출처: … (기간)\n지표 뜻 한 줄(예: 온라인 언급 · 반응량 지표이며 맛 · 매출 순위가 아님)"
}
```
- `items[0]` 이 1위다. 이미지에는 1위를 "?" 로 가리고 2위부터 보인다. 개수 = TOP N(10~15)
- `title` 은 짧게(한 줄, 12자 안팎). 길면 스크립트가 글자를 줄인다
- `hint` 는 2줄, 사실만(예: "2 · 3위를 제치고 1위에 오른 ○○는?"). 확인 안 된 "또 1위" · "N달 연속" 은 쓰지 않는다
- `stat` 은 자료에 있는 수치만. 없으면 조사 대상 · 기간 한 줄
- `items` 의 한 칸은 이름만(`"진라면"`) 또는 `["이름", "값"]`(예: `["55~59세", "5억 4천"]`). 값이 있으면 오른쪽에 주황 숫자로 붙는다
- 색은 밝은 판(라이트) 하나로 고정. `theme` 은 쓰지 않는다

### 구간표 모양("나는 상위 몇 %?")
```json
{"layout": "tier", "badge": "2024 가계금융복지조사", "title": "30대 연봉,", "title2": "나는 상위 몇 %?",
 "stat": "조사 대상 · 기준 한 줄", "rows": [["상위 1%", "값"], ["상위 10%", "값"], ["상위 50%", "값"]],
 "image": "주제그림.png", "cta": "너는 어디쯤이야? 댓글로 알려줘", "source": "출처 …"}
```
- `rows` 5~12개, 위가 가장 좁은 칸(상위 1%)이고 아래로 갈수록 넓어진다. 1위 가리기 없음
- 값은 공식 통계에 나온 구간값만 쓴다. 통계에 없는 구간을 계산 · 추정해 채우지 않는다

### 주제 그림(`image`, 두 모양 모두)
- 자료 JSON 과 같은 폴더의 그림 파일 이름. 제목 오른쪽 위에 330~360px 로 놓인다
- **1순위: Microsoft Fluent Emoji 3D**(MIT 사용권, 무료, 바탕 투명) — `https://raw.githubusercontent.com/microsoft/fluentui-emoji/main/assets/<이름>/3D/<이름_소문자_밑줄>_3d.png` (예: `Steaming%20bowl/3D/steaming_bowl_3d.png`). 주제를 한눈에 알 수 있는 사물 하나를 고른다(라면=김 나는 그릇, 치킨=닭다리, 커피=뜨거운 음료, 아파트=건물, 돈=돈주머니)
- **2순위: Cloudflare Workers AI(FLUX, 무료 하루 10,000 뉴런)** — 주제에 맞는 이모지가 없을 때만 쓴다(Gyan 결정 2026-10-31)
  1. `gh api -X POST repos/leegyan/insta-publisher/actions/workflows/gen_image.yml/dispatches -f ref=main -f inputs[tag]=<slug> -f 'inputs[requests]=[{"name":"img","prompt":"<사물 하나를 영어로 구체적으로>"}]'` (토큰은 저장소 Secret 에만 있다)
  2. 약 60초 뒤 `gh run list -R leegyan/insta-publisher -L 1 --workflow gen_image.yml` 이 success 인지 보고, `gh api "repos/leegyan/insta-publisher/contents/<slug>/img.png?ref=images" -H "Accept: application/vnd.github.raw" > <자료 폴더>/img.png`
  3. 받은 그림을 Read 로 열어 본다: 그림 속 글자 · 숫자, 외국 화폐(달러 · 비트코인 등), 상표, 사람 얼굴이 있으면 프롬프트를 바꿔 한 번만 다시 만든다. 그래도 있으면 그림 없이 그린다
  4. 사물 하나만 요청한다(여러 사물은 배경 지우기 · 자르기가 덜 됨). 배경은 cf_image.py 가 투명하게 지운다
- Creative Claw 등 돈이 드는 생성 도구와 Figma 는 쓰지 않는다. 둘 다 맞지 않으면 그림 없이 그린다(`image` 를 빼면 제목이 넓게 놓인다)
- 사람 얼굴 · 상표 로고 · 실제 브랜드 제품 사진은 쓰지 않는다

## 3. 이미지 → 영상 → 대기열
1. 자료 JSON(2절)을 `/tmp/pub/<slug>.json` 으로 쓰고 `python3 ranking/render.py /tmp/pub/<slug>.json /tmp/pub/<slug>.png` (1080×1920. 글꼴은 ranking/fonts). 화면 밖으로 나간 글자가 있으면 멈추니 자료 글 길이를 줄여 다시 그린다
   - 주제 그림(2절)을 먼저 같은 폴더에 받아 둔다
   - Figma(figma_fill.js)는 옛 어두운 디자인의 예비 수단이다. Figma 무료 플랜은 MCP 호출이 월 20회라 매일 쓰지 않는다
2. PNG 를 Read 로 직접 열어 본다: 글자 겹침 · 잘림 · 순위 누락이 없어야 한다. 있으면 자료(글 길이)를 고쳐 다시 그린다
3. 캡션(아래 4절)을 `캡션.txt` 로 쓴다
4. `bash ranking/make_reel.sh <PNG> <캡션.txt> /tmp/pub/<slug>` — 배경음은 ranking/bgm/ 의 자체 제작 곡(01_경쾌 · 02_웅장 · 03_긴장 · 04_통통)을 날짜 + 시각(KST 시)으로 돌려 쓴다(하루 5편이 서로 다른 곡이 되도록)
5. `python3 enqueue.py /tmp/pub/<slug> myeotwi.ya <오늘>T<게시 시각>:00+09:00 --reel /tmp/pub/<slug>/릴스/1판` — 1편째 11:00, 2편째 14:00, 3편째 17:00, 4편째 20:00, 5편째 22:00(릴스 + 같은 영상 스토리). enqueue.py 가 넣을 때마다 게시 워크플로우를 실행하지만 아직 시각이 안 된 편은 올라가지 않는다
6. 5편을 모두 넣은 뒤 한 번만: `gh api -X POST repos/leegyan/insta-publisher/actions/workflows/slots.yml/dispatches -f ref=main -f 'inputs[times]=11:00 14:00 17:00 20:00 22:00'` → 1분 뒤 `gh run list -R leegyan/insta-publisher -L 1 --workflow slots.yml` 가 in_progress 인지 확인한다. 이미 지난 시각은 바로 실행된다. 하루에 slots.yml 은 한 번만 실행한다(다시 실행하면 앞 실행이 취소되고 새 실행이 이어받는다)
7. `사용소재.md` 표에 한 줄 더하고 main 에 커밋 · 푸시한다(글만. 이미지는 main 에 넣지 않는다)

## 4. 캡션 형식
```
<제목> TOP<N> <이모지 1개>
<힌트 질문 한 줄>...?

.
.
.

두구두구두구 🥁

바로 <1위> 👑
<1위에 대한 자료 속 사실 1~2줄>

너의 최애 <대상>은 몇 위야? 댓글로 알려줘 👇

*<출처 · 기간 · 조사 규모>. <지표 뜻 · 한계>

#해시태그 5개
```
- 해시태그는 5개(인스타그램 최대치), 모두 사람들이 검색할 낱말로 채운다. 계정 이름 태그는 넣지 않는다
- 순서 고정: ① 대상(#치킨) ② 대상+순위(#치킨순위) ③ 달+브랜드평판(#10월브랜드평판) ④ 1위 이름+추천(#BHC추천) ⑤ 대상+추천(#치킨추천)
- 자료가 브랜드평판이 아닐 때만 ③ 은 달+자료 이름(예: #10월앱순위)으로 쓴다(자료와 다른 태그를 달지 않기 위함)
- 내용과 맞지 않는 말(예: 맛집 내용이 아닌데 #치킨맛집)은 쓰지 않는다
- 구간표(유형 A · B)는 1위를 가리지 않으므로 "두구두구" 대신 `<제목>` 다음 줄에 "너는 어디쯤이야? 댓글로 알려줘 👇", 그다음 구간표의 값을 글로 한 번 더 적고(상위 1% ○○ · 10% ○○ · 50% ○○), 출처 줄을 쓴다. 해시태그 ③ 은 연도+자료 이름(예: #2025연봉, #가계금융복지조사), ④ 는 대상+상위(예: #연봉상위), ⑤ 는 대상+비교(예: #연봉비교)
- 근거: 조회수 상위 랭킹 릴스(tap.pick · narabi_index)의 해시태그 형식(INSTA 주제/랭킹/조사_랭킹계정_20261030.md)

## 5. 결과 보고(세션 마지막)
소재 · 출처(링크) · 1위 · 대조한 출처 수 · 대기열에 넣은 게시물ID · 게시 예정 시각 · 문제(있으면). 실패하면 무엇이 어디서 실패했는지.
